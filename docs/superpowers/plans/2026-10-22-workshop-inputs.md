# Workshop Inputs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A city's workshop transforms inputs into its good, produces in proportion to its scarcest input, and the inputs its workshops need count in the city's demand.

**Architecture:** Core gets a recipe on `MarketGood` (`MarketInput` list) and `CityMarket` consumes inputs in `StartDay`, exposes the input need and the demand (consumption + input need) that thresholds, starting stocks and the AI planner read. Game gets the recipe on `GoodDefinition`, validated and converted by `EconomyDefinition`. The debug tools get two indicators and an "Intr." column.

**Tech Stack:** Unity 6000.6.4f1, C#, NUnit EditMode tests, UI Toolkit.

**Spec:** `docs/superpowers/specs/2026-10-22-workshop-inputs-design.md`

## Global Constraints

- All code, comments, asset names in English; everything the player or the debug tools show in French.
- Nothing in the repository names the game this one is inspired by (code, comments, rules, commit messages).
- Simulation logic in Core (no `MonoBehaviour`), covered by EditMode tests; definitions in ScriptableObjects only.
- In Core a good is its index among the **active** goods; an input whose good is not active is left out of the recipe.
- `CityMarket.LastDay` only copies values the day already computes.
- Order of a day unchanged: inhabitants consume every good first, then the city's workshops in the catalogue's order.
- Tests run with the `run-tests` skill (Editor open: through unity-mcp; closed: batch mode). Never edit `.sln`/`.csproj`.
- Assets created, moved or deleted with their `.meta`.
- Commits on `main`, messages in French, prefixed "Intrants : ".

## Review Focus

- A workshop with 0 workers (or a good not produced) has a need of 0: its factor is 1, never a division by zero or NaN in a stock. → Task 2 test `AWorkshopWithoutWorkers_TakesNothing_AndNoStockBecomesNaN`.
- Two workshops sharing a scarce input: the first in the catalogue's order takes what it needs, the next gets what is left. → Task 2 test `TwoWorkshops_ShareAScarceInput_InTheCataloguesOrder`.
- Floating-point rounding never leaves an input stock below 0 after a workshop takes all of it. → Task 2 test `AnInputTakenWhole_LeavesAStockOfZero_NotBelow`.
- An inefficient city's workshop needs inputs per unit it actually makes (its lower output), not per nominal unit. → Task 4 test `AnInefficientWorkshop_NeedsInputsForWhatItMakes`.
- A recipe whose input good is switched off: the workshop works with its other inputs, or with none. → Task 4 test `AnInactiveInput_IsLeftOut_TheWorkshopNeedsOnlyTheOthers`.

- [ ] **Step 3: Implement.** In `StartDay`'s workshop loop, after hiring/laying off, for a produced good:

```csharp
double potential = workers[i] * good.DailyOutputPerWorker;
double factor = 1d;
foreach (MarketInput input in good.Inputs)
{
    double needed = potential * input.UnitsPerUnit;
    if (needed > 0d) factor = Math.Min(factor, stocks[input.Good] / needed);
}
foreach (MarketInput input in good.Inputs)
{
    double needed = potential * input.UnitsPerUnit;
    double taken = needed * factor;
    stocks[input.Good] = Math.Max(0d, stocks[input.Good] - taken);
    weekLog.AddInputs(input.Good, taken);
    LastDay.AddInputs(input.Good, needed, taken);
}
if (WorkforceRule.ProducesAt(stocks[i], goodThresholds)) { produced = potential * factor; stocks[i] += produced; }
```

Keep `weekLog.Record(i, produced, consumed[i])`; it must not overwrite the inputs (separate array). Note the `ProducesAt` check reads the good's stock after hiring as today.
