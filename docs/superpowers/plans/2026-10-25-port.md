# Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every city's grid gets a 4×3 port, half on water and half on land, placed only in the City Layout window, with four facings; a layout without one is unusable.

**Architecture:** `Core` learns the port as a new `BuildingKind`, placed through its own `CityGrid` entry point that checks the water/land split from a `PortSite` (origin + facing). The grid's existing forbidden cells *are* the water cells (names kept, comments updated). `Game` adds `PortDefinition` to the catalogue and the port to `CityLayoutDefinition`; the Editor layout window gets a Port tool; the city view draws the port with two generated placeholder sprites, mirrored for the other two facings.

**Tech Stack:** Unity 6000.6.4f1, C#, NUnit EditMode tests, IMGUI (layout window), SpriteRenderer (city view).

**Spec:** `docs/superpowers/specs/2026-10-25-port-design.md`

## Global Constraints

- All code, comments, asset names in English; the player-facing name of the port is French: **"Port"**.
- Never name the inspiration game anywhere (code, comments, rules, commit messages).
- Port footprint **4×3** (width 4 on x, depth 3 on y, `Along`); **2** water rows (the front), **1** land row (the back).
- Facings: **North = +y, East = +x, South = −y, West = −x**. North/South → `BuildingOrientation.Along`; East/West → `Across`. R turns North → East → South → West → North.
- The port is not a network root, never connected, never darkened, not in the build bar, costs nothing.
- Only the port may cover water (forbidden) cells; `CityGrid.CanPlace` is unchanged.
- Create/move assets with their `.meta`; never edit `.sln`/`.csproj`.
- Run tests with the `run-tests` skill (Editor usually open: `Unity_RunCommand`). Commit on `main` at the end of each task, no push.
- Every new scene reference or data asset goes through `WorldMapSetup.Build` / `CityViewSetup` (create when missing, leave existing untouched).

## Review Focus

1. **Facing ↔ water rows mismatch** — for each of the 4 facings, the two water rows are exactly the two on the facing side; a test per facing places the port on a strip of water matching that facing and refuses the three other facings at the same origin (Task 1, `CanPlacePort_EachFacing_NeedsWaterOnItsSide`).
2. **Port not touching the network** — a road touching only the port is not a network road, and a house touching only that road stays unconnected (Task 1, `ARoadTouchingOnlyThePort_IsNotANetworkRoad`).
3. **Editing operations silently dropping the port** — every `CityLayoutEditing` operation that rewrites the content (add house, roads, water brush, town hall, resize, auto-connect) keeps the port (Task 3, `EveryEdit_KeepsThePort`).
4. **Auto-connect placing the town hall or a road under the port's land row** — `AutoConnect` builds its grids with the port on them (Task 3, `AutoConnect_KeepsClearOfThePort`).
5. **Mirroring giving the wrong facing in the view** — the sprite/flip chosen for each facing is a pure function and is tested (Task 4, `PortSpriteOf_EachFacing`).
